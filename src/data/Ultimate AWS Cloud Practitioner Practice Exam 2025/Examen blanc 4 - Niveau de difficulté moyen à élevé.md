Question 17Ignoré  
Quels moteurs de cache sont pris en charge par AWS ElastiCache ?  
**Bonne réponse**  
Redis et Memcached  
Redis et MongoDB  
Apache Spark et Apache Flink  
Cassandra et Elasticsearch  
Explication générale  
AWS ElastiCache est un service de mise en cache entièrement géré proposé par Amazon Web Services, prenant en charge deux moteurs de cache : Memcached et Redis. Ces moteurs améliorent les performances des applications en réduisant la charge sur la base de données et en optimisant les temps de réponse. Memcached est un moteur de cache simple et rapide qui stocke les paires clé-valeur en mémoire, tandis que Redis est un système de stockage de données en mémoire pouvant servir de base de données, de cache et de courtier de messages. Hautement évolutifs, flexibles et disponibles, ces deux moteurs sont parfaitement adaptés au développement d'applications hautes performances dans le cloud. AWS ElastiCache fournit un environnement sécurisé et géré pour le déploiement et l'administration de ces moteurs de cache.

Question 41Ignoré  
Quel est le nombre maximal de connexions VPN par interface virtuelle AWS Direct Connect ?  
2  
1  
**Bonne réponse**  
Il n'y a pas de limite  
6  
4  
Explication générale  
Il n'y a pas de limite au nombre de connexions VPN pouvant être établies sur une même interface virtuelle AWS Direct Connect. Toutefois, la bande passante totale de toutes les connexions VPN sur une même interface virtuelle ne peut pas dépasser la bande passante de cette interface. Par exemple, si vous disposez d'une interface virtuelle de 1 Gbit/s, vous pouvez établir jusqu'à 10 connexions VPN de 100 Mbit/s chacune, ou une seule connexion VPN de 1 Gbit/s.

Explication générale  
Pour répondre aux exigences d'une base d'utilisateurs mondiale avec une application hautement disponible et une latence réduite, la meilleure approche d'architecture AWS est généralement une architecture multirégionale active-active (option B).

Cette architecture consiste à déployer l'application sur plusieurs régions, chacune disposant d'instances actives qui gèrent le trafic. Les utilisateurs peuvent ainsi accéder à l'application depuis une région voisine, ce qui réduit la latence et améliore l'expérience utilisateur. De plus, en cas de panne dans une région, le trafic est automatiquement redirigé vers d'autres régions actives, garantissant une haute disponibilité et minimisant les interruptions de service.
